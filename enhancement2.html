JavaScript enhancements

These are the five JavaScript enhancements on top of the Assignment 2 requirements. They are listed from the hardest to build (1) to the easiest (5). All the code is in scripts/enhancements.js, one function for each enhancement, with comments in the file. Each one below says how it is triggered, what a programmer has to do to build it, and where you can see it on the site. The CSS enhancements from Assignment 1 are on the Enhancements 1 (CSS) page.

1. Identify a plant from a photo

How it is triggered: on the Identify page or the Contribute page, choose a photo of a plant, say whether it shows a leaf, flower, fruit, bark or the whole tree, and press Identify this plant. After a moment the page lists up to three best guesses with the family, a common name and a percentage score. Pressing Use this name puts the guess into the “Plant’s name” box. If the photo has no plant in it, the service is out of requests for the day, or there is no connection, a message says so.

How it works: the page sends the photo to the Pl@ntNet identification API. A FormData object holds the photos (up to five) and one organ value for each, and fetch() sends it as a POST request to my-api.plantnet.org/v2/identify/all with my API key in the address. The reply is JSON: a list of species sorted by score, each with its scientific name, family and common names. Canopy.identifyResults builds the list with createElement and uses Math.round to turn the score into a percentage. Each response status is handled on its own (404 no plant found, 429 daily limit reached, other errors, and catch for no connection), and the button is disabled while the request is running. The free plan allows 500 identifications a day, and the key must be set to “expose my API key” with the site’s address on its allowed domains before a browser may use it. The service may not know every Sarawak species, so the guesses are only suggestions.

See it on: Identify (photo only, with a link to the species profile when a guess is one of our eight species) and Contribute (with a button that fills in the plant name).

Reference: Pl@ntNet API documentation (third-party service), MDN Web Docs – Using the Fetch API, MDN Web Docs – FormData.

2. Sending the form to an API

How it is triggered: fill in the Enquiry or Contribute form correctly, press Submit and then Confirm and send in the preview. The page stays where it is, shows “Sending...” and then a green thank-you message, and the form is cleared. If something goes wrong, a red message says so instead. The data arrives in my email.

How it works: the site has no server of its own, so the form is sent to Web3Forms, a free form API. Each form has a hidden access_key field. Canopy.sendForm builds a FormData object from the form and sends it with fetch() as a POST request. The reply is JSON, and result.success decides which message is shown. Network failures are caught with catch. The free plan does not accept files, so for the photo field only the file names are sent. The same address is in the form's action attribute, so the form still works if JavaScript is off.

See it on: Enquiry and Contribute.

Reference: Web3Forms documentation, MDN Web Docs – Using the Fetch API, MDN Web Docs – FormData.

3. Preview pop-up before a form is sent

How it is triggered: fill in a form correctly and press Submit. Instead of sending straight away, a pop-up lists everything you entered. Edit closes the pop-up so you can change something, and Confirm and send sends the form.

How it works: Canopy.setupPreview listens for the submit event after the validation in script.js has run. If nothing was wrong, it calls event.preventDefault(), builds a dialog element from the form's fields (Canopy.collectValues) and opens it with showModal(). The confirm button calls Canopy.sendForm (enhancement 2). If the browser does not support dialog, the form is sent as normal.

See it on: Enquiry and Contribute.

Reference: MDN Web Docs – HTMLDialogElement.showModal().

4. Plant slideshow

How it is triggered: open the home page. A slideshow of the eight species starts on a random plant and changes by itself every five seconds, with a fade. You can use Previous and Next, press the left and right arrow keys, click a dot to jump to a plant, or press Pause. It stops while the mouse or keyboard focus is on it, and it starts paused for visitors whose device is set to reduce motion.

How it works: the eight plants are an array of objects in Canopy.slides. Canopy.setupSlideshow builds the picture, text, buttons and dots with createElement, and keeps the current position in a variable. show() replaces the content and wraps around at the ends with a remainder (%). setInterval() moves on every five seconds and clearInterval() stops it. Mouse, focus and keydown listeners pause it and handle the arrow keys, window.matchMedia() checks the reduced-motion setting, and aria-current and aria-live keep it usable with a screen reader.

See it on: the home page.

Reference: MDN Web Docs – setInterval(), MDN Web Docs – Window.matchMedia().

5. Search and filter the species

How it is triggered: on the Species page, type in Search the species or choose a Conservation status. The profiles and gallery pictures that do not match disappear while you type, and a line says how many are showing (for example “Showing 2 of 8 species”). Clear puts everything back. Searching for a local name such as “keruing” also works.

How it works: Canopy.setupSpeciesFilter builds the search box, the menu and the count with createElement. The menu options are not typed in: a regular expression in Canopy.statusOf reads the first words of each profile’s Status line (for example “Least Concern”) and the unique ones are sorted into the menu. An input or change listener then compares the lower-case textContent of each profile with the search text and the chosen status, and uses classList.toggle to add or remove a filtered-out class (display: none). Each gallery picture is hidden when the profile it links to is hidden.

See it on: Species.

Reference: MDN Web Docs – input event, MDN Web Docs – Node.textContent.

Other JavaScript on the site

These four are also written in enhancements.js but are not counted as enhancements. The dropdown and the live feedback belong to the Assignment 2 requirements (the menu built from an array and the form validation), and the menu highlight is a very small feature.

Dropdown menu opened with JavaScript. On a wide screen, moving the mouse onto Explore slides open Families, Genera and Species. The CSS holds only the look (closed with max-height: 0); Canopy.makeDropdown adds the open class from mouseenter, mouseleave (with setTimeout), focusin, keydown (Esc) and click listeners, and sets aria-expanded. On a touch screen the first tap opens it and the second follows the link.

Menu highlights the current page. The link for the page you are on is bold and underlined. Canopy.highlightCurrentPage reads window.location.pathname and adds the active class and aria-current="page" to the matching menu link.

Saved draft and comment counter. What you type in the Enquiry and Contribute forms is kept in the browser (localStorage) and put back if you come back later or reload. It is cleared when the form is sent or reset. A counter under the comment box shows how many characters were typed. Canopy.saveDraft, restoreDraft and clearDraft do the saving, with JSON.stringify and JSON.parse.

Live feedback while typing. Leave a form field and a message appears under it, and the border turns green or red; it updates on every key press. Canopy.setupLiveFeedback uses the same regular expressions as the submit check and adds blur and input listeners. See it on Enquiry and Contribute.

Third-party code

I wrote all the code in enhancements.js myself, using the MDN pages listed above to check how each function works. No library or copied script is used. The only third-party parts are the Web3Forms service in enhancement 2 and the Pl@ntNet service in enhancement 1. All sources are also listed on Acknowledgement 2.
